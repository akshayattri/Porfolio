01 / The problem

A clear next step
at every stage.

Creating, preparing, promoting, and reviewing a webinar span many different tasks. When every setting carries the same visual weight, the next action becomes difficult to find.

Design goal

Make the dashboard a reliable starting point for creating an event, resuming work, and understanding performance.

A confident event starts
with a confident host.

Scenario: an educator or marketer returns to prepare a webinar while balancing content, audience communication, and a deadline.

Says / illustrative voice

“Show me what still needs my attention.”

A clear event summary is more useful than a long list of disconnected settings.

Thinks / likely questions

Is everything ready?

Are the schedule, pages, presenters, and messages aligned? Which event should I work on next?

Does / task context

Moves between planning and checking.

Creates an event, revisits setup, manages audience touchpoints, and returns to results or replay.

Feels / working hypothesis

Responsible for every detail.

Uncertainty can rise as delivery approaches. Visible status and contextual actions can support a sense of control.

The interface implication

Surface the next action, preserve event context, and separate preparation from performance review.

Scenario-based empathy map: user needs and feelings are hypotheses for validation.

03 / Design process · The dashboard

From many capabilities
to three clear intentions.

The dashboard’s organizing logic is simple: start something new, return to work in progress, or understand what happened.

01
Understand the work

Frame the host’s jobs

Separate creating an event, preparing it, engaging an audience, and reviewing results. The dashboard must orient the host across this lifecycle.

Output / task model
02
Map the structure

Give each level a role

Keep product-wide destinations in the sidebar, creation routes on Home, and detailed setup inside each webinar. This prevents the dashboard from becoming a settings directory.

Output / workspace & event hierarchy
03
Prioritize the surface

Create. Resume. Review.

Use explicit format choices for starting, recent webinars for returning, and a distinct performance area for reviewing. Each region answers a different user intention.

Output / content hierarchy
04
Build a repeatable UI

Make recognition easier

Repeat card anatomy, align metric values with labels, and reserve violet for interactive emphasis. Consistency helps dense information remain scannable.

01
DECISION / ORIENTATION

A summary before
the settings.

I gave the individual webinar a dedicated overview. Summary information helps the host re-establish context before moving into detailed configuration.

Tradeoff: more configuration areas remain visible in the event navigation. Grouping by task keeps that depth structured.

Decision & tradeoff

Approach

Group configuration around the event, with an overview before detailed settings.

Risk addressed

A host can lose context when a long settings list becomes the starting point.

Why this direction

The summary restores orientation; task-based tabs preserve access to deeper controls.

05 / Interaction patterns

Let the structure
carry the complexity.

For engagement and notifications, I used repeated rows instead of independent control groups. Alignment makes timing, state, and actions easier to compare across items.

Keep actions tied to their object

Row actions sit beside the item they affect; the add action operates at the list level.

Use quiet surfaces

White and pale neutral backgrounds keep configuration labels and controls more prominent than decoration.

EasyWebinar AI / From intent to a launch-ready webinar

Start with a conversation.
Build the whole experience.

I designed EasyWebinar AI to help hosts turn an idea into the assets around a webinar—registration and thank-you pages, emails, polls, a script, and offers—in one connected workspace.

The product shift

From configuring each asset separately to preparing a coordinated webinar through conversation.

01 / Describe

Share the topic, audience, and goal.

02 / Shape

Guide the direction through focused choices.

03 / Create

Prepare the supporting webinar assets.

04 / Review

Inspect, edit, and prepare for launch.

Decision / Reduce the blank-prompt burden

Show what the assistant can help with.

A free-text prompt gives experienced hosts flexibility. Suggested tasks—create a webinar, write a script, design a registration page, or generate polls—make the capabilities visible to someone starting for the first time.

Decision / Keep work recoverable

Give conversations a place to live.

A searchable conversation list provides a way back to earlier work. The assistant sits within the familiar product shell, connecting AI creation to the wider webinar workspace.

Conversation design

Ask a useful question.
Make it easy to answer.

I paired natural-language conversation with structured answer choices. A host can select an audience or tone instead of composing a detailed instruction from scratch, while a custom-answer route preserves flexibility.

The tradeoff: suggestions make decisions easier, but must leave room for an audience or voice that doesn’t fit a preset.

One brief / A connected set of assets

The webinar is more
than its presentation.

The AI capability extends across the attendee journey. The design goal is to carry the host’s topic, audience, and tone into each asset rather than making every piece a separate starting point.

Decision / Keep the result visible

A conversation on one side.
The outcome on the other.

The split workspace keeps the host’s instructions beside the generated page. Device previews, “Edit in Builder,” and “Save Changes” make the output something the host can inspect and refine.

Beyond the first draft

Bring help to the task.

A compact assistant panel supports actions such as adjusting a schedule, adding a session, updating pricing, or inviting a moderator. This extends AI beyond content generation into ongoing webinar management.

How AI enhances the product

Less starting from scratch.
More of the launch in one place.

Conversation offers a common entry point, guided answers help define intent, and connected previews keep creation close to review. The intended benefit is a shorter path from idea to launch, with the host retaining the final editorial decision.

The four Figma screens show the starting workspace, guided conversation, registration-page review, and contextual assistant. Faster preparation is the product goal; no measured time-saving or conversion uplift is claimed here.

01 / The starting point

The event is only
part of the work.

For a host, delivering a webinar means coordinating content, schedules, audience engagement, communications, and replay. My design challenge was to make this breadth navigable without reducing the product’s capabilities.

I organized the experience around two levels: a workspace for managing webinars and a focused environment for configuring each event.

The problem statement

A host needs a clear next step at every stage.

Managing a webinar spans creation, event setup, promotion, live delivery, and follow-up. When these tasks carry equal visual weight, a host can lose sight of readiness, the next action, and the results that matter.

Design goal

Make the dashboard a clear starting point: create the right event, resume existing work, and review performance without losing context.

Illustrative host scenario

“What needs my attention before I go live?”

A host returns to a scheduled webinar and needs to check the session time, registration setup, and presenter team before entering the room.

Design response: I brought those details into the webinar overview, with related configuration grouped into event-level tabs. The host can review the event and move directly to the next task.

The complete webinar overview brings scheduling, registration, and the presenter team into one workspace.

Scenario reconstructed from the interface to explain the design rationale; not a reported research finding.

02 / Understanding the host · Empathy map

A confident event starts
with a confident host.

Scenario: an educator or marketer returns to prepare a webinar while balancing content, audience communication, and a deadline.

Says / illustrative voice

“Show me what still needs my attention.”

A clear event summary is more useful than a long list of disconnected settings.

Thinks / likely questions

Is everything ready?

Are the schedule, pages, presenters, and messages aligned? Which event should I work on next?

Does / task context

Moves between planning and checking.

Creates an event, revisits setup, manages audience touchpoints, and returns to results or replay.

Feels / working hypothesis

Responsible for every detail.

Uncertainty can rise as delivery approaches. Visible status and contextual actions can support a sense of control.

The interface implication

Surface the next action, preserve event context, and separate preparation from performance review.

Scenario-based empathy mapping informed by the product workflows; the illustrative voice and emotional needs are hypotheses, not participant quotations.

03 / Design process · The dashboard

From many capabilities
to three clear intentions.

The dashboard’s organizing logic is simple: start something new, return to work in progress, or understand what happened.

01
Understand the work

Frame the host’s jobs

Separate creating an event, preparing it, engaging an audience, and reviewing results. The dashboard must orient the host across this lifecycle.

Output / task model
02
Map the structure

Give each level a role

Keep product-wide destinations in the sidebar, creation routes on Home, and detailed setup inside each webinar. This prevents the dashboard from becoming a settings directory.

Output / workspace & event hierarchy
03
Prioritize the surface

Create. Resume. Review.

Use explicit format choices for starting, recent webinars for returning, and a distinct performance area for reviewing. Each region answers a different user intention.

Output / content hierarchy
04
Build a repeatable UI

Make recognition easier

Repeat card anatomy, align metric values with labels, and reserve violet for interactive emphasis. Consistency helps dense information remain scannable.

01
DECISION / ORIENTATION

A summary before
the settings.

I gave the individual webinar a dedicated overview. Summary information helps the host re-establish context before moving into detailed configuration.

Tradeoff: more configuration areas remain visible in the event navigation. Grouping by task keeps that depth structured.

02
DECISION / RECOGNITION

Show the content.
Don’t just name it.

Page previews provide visual recognition across the registration, confirmation, and waiting experience. Supporting content is grouped beneath, so the page sequence remains the first point of attention.

The organizing idea:
one event,
many connected tasks.
05 / Interaction patterns

Let the structure
carry the complexity.

For engagement and notifications, I used repeated rows instead of independent control groups. Alignment makes timing, state, and actions easier to compare across items.

Keep actions tied to their object

Row actions sit beside the item they affect; the add action operates at the list level.

Use quiet surfaces

White and pale neutral backgrounds keep configuration labels and controls more prominent than decoration.
